# 本地 Dense 实验结果

## BGE-M3 与 308 题重跑（2026-11-10）

- 正式评估使用 `configs/stard_final_308_v6.json` 的 308 题、512 对题目与参考条文。试跑使用 1023、591、683，均在正式题单之外。
- 本地 BGE-M3 使用 BAAI revision `5617a9f61b028005a4858fdac845db406aefb181`。全库向量在 RTX 3060 Laptop GPU 上按 FP32、CLS 池化、L2 归一化、最长 512 token 生成。在线阶段在 CPU 上运行，三组复用同一份语料向量缓存。
- 每题从同一份领域目录出发。Hybrid 和 POST 对目录内全部条文检索。PRE 先由 Jev 选两份文件，再对两份文件内全部条文检索。三组用完整排名做 RRF（常数 60），POST 重排前 30 条，最终均输出前 10 条。
- 原始过程日志和建库记录位于 `artifacts/bge-m3-final-308-v6/`。本地 Jev 预算账本为 `artifacts/jev-budget.sqlite3`。

全库 55,348 条的向量缓存已生成，维度 1,024，缓存文件字节数核对一致。GPU 编码 1,425.75 秒，含加载及缓存写入 1,431.39 秒，PyTorch 报告峰值 GPU 张量分配约 2,942 MiB。在线运行使用 Python 3.12.4、CPU 版 PyTorch 2.3.1，线程数设为 4。Jev 固定为 `jev-1.14.0`。

试跑三组均完成，6 次 Jev 调用共 58,092 个输入 token。正式三组均于北京时间 2026-11-10 16:33 前完成，每组 308 题。汇总脚本验证了题号与顺序、语料版本和向量缓存一致，领域目录逐题一致，POST 重排前的 Top-10 与 Hybrid 逐题一致。

## 历史设置与结果

本报告记录当前实现的可复现摘要；原始 `artifacts/`、模型缓存和 provider
响应均不提交到 Git。它们保留在执行机器上，运行 ID 为
`full-dev-*` 与 `full-final-*`。

## 设置

- 数据：STARD，处理后数据哈希
  `d2bc0bf33155184c150c400cf1b29e03230e0dfc5c0a098dac5fdb3a59020482`。
- 开发集：固定 `tune_train` 600 题；保留评估集：309 题。
- 共同设置：22 个领域按本地 `BAAI/bge-small-zh-v1.5` 相似度排序。从
  Top-4 起按文件并集动态缩减到不超过 255 份文件。BM25 Top-1000 与
  Dense Top-1000 以 RRF（常数 60）融合，最终输出 Top-10。
- 原有三种方法每题选择 2 份文件。补充对照在领域筛选后直接检索保留文件的全部条文。
- Dense 后端：本地 `BAAI/bge-small-zh-v1.5`，不是 SiliconFlow BGE-M3。
  结果不得与远程 BGE-M3 运行混合比较。
- 方法二：Jev Choice 按完整领域目录中的文件 ID 和标题概率选择前 2 份文件。
- 方法三：Jev Choice 对 RRF 条文候选按“名称 + 正文”重排。

宏平均，字符数统计条文名称和正文，用于比较候选输入规模。

| --- | ---: | ---: | ---: | ---: | ---: |
| 方法一：标题相似度基线 | 0.1348 | 0.1181 | 0.1036 | 0.8569 | 0.1767 |

### 补充对照：领域内直接 Hybrid（2026-11-09）

使用同一数据哈希下 `splits.json` 的 309 个 `final` 题号，只运行补充对照。
领域筛选平均保留 207.06 份文件、9,400.11 条条文。BM25 和 Dense 各在这一
范围内取 Top-1000，直接返回 RRF Top-10。领域条文保留率与原报告一致，首位
命中 91/309 题。

直接检索相对标题相似度选两份文件，Recall@10 提升 33.88 个百分点，nDCG@10
提升 26.16 个百分点。Jev 前置选文件相对直接检索，Recall@10 高 2.05 个百分点，
nDCG@10 高 2.77 个百分点，Hit@1 高 5.50 个百分点。

本机四线程 CPU 查询的 P50、P95 和平均延迟分别为 790.36、1,001.23 和
796.40 ms，Jev 请求数和 API 费用均为 0。语料向量来自同版本 BGE 的本地缓存，
55,348 条语料的分词输入已逐条核对。该延迟为本机测量，硬件环境与原表分开记录。
逐题排名、参数和统计位于 `artifacts/runs/full-final-domain-hybrid/`，运行脚本位于
`artifacts/run_final_domain_hybrid.py`。

### 255 份文件上限的裁剪对照

根据已有 309 题的逐题领域排序复算，初始前 4 个领域的标准条文保留率为 89.86%。
整域移除后降到 85.69%，共丢失 24 个「问题—标准条文」匹配，涉及 16 题，其中
10 题失去了候选范围内的全部标准条文。

在固定 600 道开发题上比较两种规则，两组共用同一领域排序和 255 份文件上限。
整域移除从前 4 个领域开始，超限时逐个移除末位领域。按文件裁剪先保留整域规则
留下的文件，再从排名最高的被移除领域中，按 BGE 标题相似度补入尚未入选的文件，
直到用满预算。若前三个领域本身已超限，第四个领域全删，第三个领域按标题裁剪。
两组最终检索均对各自保留的全部条文打分，BM25 和 Dense 的完整排名参与 RRF。

| 裁剪规则 | 平均文件数 | 标准条文保留率 | 相对初始前 4 域丢失的匹配数 | Recall@10 | nDCG@10 | Hit@1 | 候选 Recall@30 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 整域移除 | 207.71 | 82.80% | 31 | 43.75% | 34.10% | 25.83% | 52.71% |
| 按文件裁剪 | 231.93 | 84.40% | 18 | 44.26% | 34.44% | 26.00% | 53.35% |

600 题中有 275 题的初始目录超限。按文件裁剪找回 13 个匹配，涉及 11 题，其中
9 题从零覆盖恢复到至少覆盖一条标准条文。最终检索点估计略高，Recall@10 差值
为 +0.51 个百分点（问题级配对 bootstrap 95% 区间 −0.21 至 +1.33），nDCG@10
差值为 +0.35 个百分点（−0.04 至 +0.83）。本对照使用本地检索，Jev 前置文件选择
在较大目录上的收益和输入开销待实测。逐题统计位于 `artifacts/runs/dev-domain-file-budget/`。

Top-10 的端到端时间；不包含进程启动时加载导航模型，也不包含首次构建本地语料
向量。六个完整运行均命中磁盘向量缓存，启动加载导航模型耗时约 2.01--2.82 秒。
因此表中延迟适合表示缓存已就绪时的单题体验，不应解读为首次部署总耗时。

估算约 **$0.82443**；缓存命中的题目不会再次产生 Jev 请求费用。

## 局限

- 本结果是本地 bge-small Dense 变体，不能宣称为远程 BGE-M3 的结果。
- 当前报告未计算问题级 paired bootstrap 置信区间；在作显著性结论前应补充。
- 领域筛选本身限制了可达召回：保留集的领域标准条文保留率为 0.8569。
